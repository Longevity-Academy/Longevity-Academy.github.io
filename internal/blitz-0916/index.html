Purchases today — read this carefully

The pixel records 3 Purchase events today, all within the 19:00–20:00 IDT hour, all from mobile_iphone, split 2 server-side and 1 browser. The deployed checkout loads the live PayPal endpoint and fires Purchase only after a completed capture against a real order number, so the payment is genuine — but a single transaction reported by both the browser and the server without shared event deduplication registers as multiple events.

Read this as one real $179 payment, counted three times. The same duplication inflates the Purchase count on paid campaign reporting, which means reported ROAS has been overstated. Fixing it requires passing a shared event_id on the browser and server calls. Confirm the true order count against the PayPal record before quoting any purchase figure.

Method and limits

Click counts come from uniquely named pixel events (OC_<community>) fired only by the tracked redirect links, so Meta paid traffic cannot register in them by construction. Funnel counts are total store activity across all sources and are not organic-only. Group membership figures are Facebook's own listed counts, which describe community size, not post impressions — impression data is not exposed to members. Every community listed as live was individually re-verified immediately before this page was published, by opening its "Your content" panel and confirming a published post. Nothing on this page is estimated or modelled.
